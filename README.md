# PIA｜产品智能研究助手

**Product Intelligence Agent（PIA）是个人完成的 AI（人工智能）产品 MVP（最小可行产品），帮助产品经理发现具有竞争意义的竞品变化，并基于可核查证据开展深入研究。**

面向产品经理、研究人员和需要关注竞品的业务团队。已实现前后端完整流程，代码开发使用 AI 编码工具辅助；当前本地单用户运行，扫描由用户触发，深入研究由用户选择启动。

![真实首页：竞争事件、证据与分诊建议](docs/assets/screenshots/home.png)

## 为什么做

问题观察：竞品信息散落在产品页、价格页和更新日志中。读到变化后，还需要判断它是否重要、与自身产品有什么关系，以及依据是否可靠。

产品假设：把采集、判断和研究串起来，可以减少人工切换与整理。项目尚无规模化用户验证、商业收益或效率提升比例结论。

## 关键 AI 产品设计

| 问题 | 设计与取舍 |
|---|---|
| 网页变化就是事件吗？ | 普通首次扫描只建基线；比较同项前后状态，或使用官方明确变化声明；不足则保留“不确定”。 |
| 哪一步需要 Agent（智能体）？ | 分诊采用固定工作流；研究才按证据缺口选择工具，由程序限制预算与校验引用。 |
| 模型怎样理解产品背景？ | RAG（检索增强生成）分开检索自身与竞品知识，避免混淆能力归属。 |
| 怎样保持关注连续性？ | Memory（长期记忆）保存用户意图，自动识别须确认，不能作为产品事实证据。 |
| 怎样验证 AI？ | Evaluation（评测）区分软件、链路与模型质量，冻结数据、防止答案泄漏并保留失败案例。 |

程序管理状态、数据作用域、工具调用与证据；模型负责语义判断和研究计划。没有登录或企业权限系统。

## 当前边界

本地单进程、手动扫描，无定时调度、登录权限、通知、扫描件文字识别或生产服务承诺。引用可追溯不等于语义完全正确；研究与记忆尚无独立质量评测。内部资料可能发送到配置的外部模型服务，使用前须评估是否允许外发。
