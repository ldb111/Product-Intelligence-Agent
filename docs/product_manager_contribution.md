# 我在 PIA 项目中的产品经理贡献

PIA（Product Intelligence Agent，产品智能研究助手）是个人 AI（人工智能）产品 MVP（最小可行产品），帮助产品经理发现具有竞争意义的竞品变化，并基于可核查证据开展深入研究。

本文按实际产品职责说明贡献，不包装多人研发团队，也不将工具辅助代码写成全部独立手写。

## 职责与可核查产出

| 职责 | 具体工作 | 依据 |
|---|---|---|
| 产品定位 | 聚焦竞品变化判断与研究，而非新闻汇总 | [产品介绍](../README.md) |
| 用户流程 | 配置、扫描、分诊、主动研究、同页追问及失败恢复 | [演示路径](demo.md)、[前端](../frontend/src/App.tsx) |
| AI能力拆解 | 区分语义判断、固定工作流和研究工具选择 | [AI架构](ai_architecture.md) |
| 智能体边界 | 事件范围、只读工具、预算与停止条件 | [研究实现](../research/agent.py) |
| 证据机制 | 区分事实、推断、建议，要求可追溯原文 | [引用校验](../research/evidence.py) |
| Evaluation（评测） | 数据身份、冻结、防泄漏与计分边界 | [评测方法](evaluation.md) |
| Bad Case（失败案例） | 区分证据缺口、语义、标注与计分问题 | [真实案例](evaluation.md#典型失败案例) |
| 产品验收 | 真实页面、引用、持久化和完整流程检查 | [历史验收](final_closure_report.md) |

## 与 AI 编码工具的协作方式

我负责提出产品目标、业务边界与验收要求，使用 AI Coding（AI辅助编程）工具协助生成、修改代码和测试，并依据真实运行结果推进问题澄清与验收。

贡献不以代码量衡量。需要能够解释为什么采用当前流程、程序与模型怎样分工、错误发生在哪一层，以及哪些能力尚未得到质量证明。

## 表述边界

这是问题观察与产品假设驱动的个人项目，没有规模化用户研究、商业运营数据或企业客户服务经历。软件通过不代表模型全部正确；承担产品职责不等于手写每一行代码。
