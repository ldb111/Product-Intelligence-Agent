# PIA 详细架构与设计理由

PIA（Product Intelligence Agent，产品智能研究助手）帮助产品经理发现具有竞争意义的竞品变化，并基于可核查证据开展深入研究。面试阅读入口见[AI（人工智能）架构](ai_architecture.md)，本文提供状态与实现细节。

## 产品边界

桌面网页支持配置、手动扫描、事件判断、研究、追问和关注管理。当前本地单用户运行，不提供后台定时监控或企业身份认证。

## 先保存状态，再判断变化

采集层保存真实快照、局部结构与同项匹配。`observed_latest` 表示最新观测，`processed_latest` 表示正式结果已可靠保存。正式事件及去重结果、待确认候选或非事件结果持久化后，才推进比较进度；分诊失败恢复自己的检查点，不重复发现旧变化。

普通首次扫描只建基线。Path A（前后状态比较）要求真实同项旧新原文；Path B（官方明确变化声明）可在没有旧快照时形成候选，程序控制有限回溯与重复处理。模型不能自行切换路径凑证据，观察时间不能代替发生时间。

## 模型与程序分工

| 环节 | 程序 | 模型 |
|---|---|---|
| 来源 | 网页读取、来源登记和数据范围 | 选择相关候选 |
| 变化 | 状态匹配、比较资格和两侧证据 | 竞争意义、三类决策与八类事件 |
| 引用 | 逐字摘录、字段关系和来源身份 | 语义支持与解释 |
| 去重 | 内容哈希、幂等和事务 | 是否同一次业务变化 |
| 分诊 | 聚合产品知识、证据和关注 | 研究、监控或无需处理的建议 |
| 研究 | 工具白名单、预算和引用验证 | 按证据缺口选择工具与回答 |
| 记忆 | 范围、生命周期和确认入口 | 从用户原文抽取长期意图 |
| 评测 | 数据冻结、防泄漏和计分 | 独立专家标注与被测预测分开 |

`uncertain`（不确定）是证据不足的出口，不使用数值置信度。自动核验补读来源后回到事件核心，不能绕过校验。

## 证据独立于模型措辞

Evidence（证据）由程序登记。模型不能创建可信地址或任意来源编号；引用须为连续原文。未知旧状态、日期和范围留空。Memory（长期记忆）和未读搜索摘要不能作为产品事实。

多个来源支持同一业务动作可以合并为一个事件；后续状态真正再次变化才是新事件。相同地址不代表相同事件，宣布、公测和正式可用不能自动合并。同源页面经事件、知识库与读页重复取得，不算独立交叉验证。

## 分诊与研究

Triage（事件分诊）采用固定检索加一次推理，没有自主搜索工具；建议研究并不自动执行。

Research Agent（研究智能体）的下一步取决于证据缺口，可检索自身知识、竞品知识、记忆、搜索和读页。程序限制最多7轮工具决策、10次工具调用、2次搜索和3次读页，随后生成并校验结果。

初始报告是独立成果。Follow-up（事件内继续追问）读取初始成果、引用、对话与问题，不覆盖原报告。用户问题先保存，回答与完成状态原子提交，故障只影响当前回合。每次研究使用独立证据登记表。

## 用户看到的研究会话

报告在上方、对话在下方，页内导航只滚动，不使用互斥标签页。回答使用自然段、列表或简单表格，引用附于被支持正文末尾，点击查看来源和逐字摘录。后台事实、推断与建议约束保留。

耗时操作在线程中执行，状态查询保持响应。刷新只查询运行状态，不重新发起任务；已完成成果不依赖浏览器内存。

## 知识与长期记忆

RAG（检索增强生成）按工作区数据库、知识域和产品范围过滤，结合向量召回与重排序返回原文。Own Product Knowledge（自身产品知识）与 Competitor Knowledge（竞品知识）分域。资料只保留当前版本参与检索，整体替换事务失败时保留旧版。

Current Focus（当前关注重点）属于显式产品配置。长期记忆保存关注、偏好与限制；自动抽取只写待确认，用户确认后才生效，不能当事实证据。当前偏好界面使用工作区范围，不提供细粒度租户授权。

## 评测与工程边界

受控测试验证状态、并发、范围与恢复，真实 E2E（端到端）验收证明配置与调用链。它们不能替代独立模型质量评测。

历史35条首次独立基线保留，参与开发后改作开发回归。新留出在发布候选冻结后选材，空候选与 Gold（金标准答案）分别提交，专家模型标注且未经真人复核，生产模型每条只执行一次。有效决策指标与包含失败的端到端指标分开。[完整方法](evaluation.md)

当前没有企业认证、扫描件文字识别、生产网络隔离或分布式恢复。逐字引用不等于完整语义验证；模型仍可能误分、漏项或误解时间角色。内部资料外发需要额外数据治理，未将这些企业能力包装成既有功能。
