# PIA 最终架构与设计理由

## 产品边界

PIA 帮产品经理从持续变化的竞品材料中识别值得行动的产品状态变化。核心输出是可追溯事件及研究，不是网页摘要堆积。PC Web 提供配置、扫描、判断、研究、追问与关注管理；当前由用户手动触发，不宣称后台定时服务。

## 状态先于判断

采集层保存不可替代的真实观测，抽取局部结构并匹配前后同项。抓到最新页面不代表已安全处理，所以 observed_latest 与 processed_latest 分开。只有正式 Event/dedup、Pending 或 no_event outcome 持久化后，comparison 才结束。Triage 失败恢复自身检查点，不重复发现旧变化。

普通首次扫描建立 baseline，不能将“第一次看到”说成“刚上线”。Path A 使用前后状态与上下文差异；Path B 接受明确官方变化声明，即便没有先前快照也可成候选。两条路不能由模型为了凑证据偷偷切换。回顾性官方声明可成立历史事件，观察时间不代替发生时间。

## 模型与程序分工

| 决策/能力 | 程序 | 模型 |
|---|---|---|
| 来源 | URL/页面读取、注册身份、输入范围 | 选取相关候选 |
| 变化 | 状态匹配、比较资格、两侧证据 | 竞争意义、三类决定、八类事件 |
| 引用 | 逐字存在、字段关系、来源身份 | 语义支持与简明解释 |
| 去重 | 内容哈希、保存与幂等 | 是否同一次业务变化 |
| 分诊 | 聚合证据、知识、关注 | research/monitor/no_action 与原因 |
| 研究 | 工具白名单、预算、引用验证 | 按证据缺口计划读取与回答 |
| 记忆 | scope、生命周期、确认入口 | 用户原文中的长期意图抽取 |
| 评测 | 冻结顺序、无泄漏投影、计分 | 独立专家标注与被测预测分离 |

没有数值置信度。uncertain 是证据缺口的真实出口，自动 Verification 可以补读来源；核验结果回 Event Core，不能直接绕过正式证据规则。搜索失败不等于没有变化。

## Evidence 独立于模型措辞

每个来源由程序登记，模型不能创建可信 URL 或任意 ID。引用必须是连续原文。Path A 每项旧/新状态都来自正确一侧，未知日期和范围留空。事实、推断与建议各有语义类别，不能把 Memory 或未读搜索摘要升级为事实。

多个来源支持同一业务动作可并入同一 Event；真正后续再次变化才是新 Event。页面 URL 相同不是事件相同。宣布、预览与正式可用可能是不同事件。同一原始来源经 Event、RAG 与页面重复取得，不成为三个独立证据。

## Triage 与 Research

Triage 是固定工作流加一次推理，因为输入已确定、目标是关注路由，没有需要自主选择的研究工具。research 只是一项建议。

Research 使用受预算约束的 Agent，因为核验与深入研究的下一步取决于已得到的证据。它可以查询自身知识、竞品知识、Memory、搜索和读页，随后停止工具调用并形成经过 Citation 校验的报告。预算限制7轮、10工具、2搜索、3读页，避免无限搜索。

Initial Report 是独立 Artifact；Follow-up 是同 Event 范围内的增量研究，以初始成果、既有引用、历史对话与当前问题为上下文。它不会覆盖原报告，也不是通用聊天。每次用户问题先持久化，回答与完成状态原子保存。故障只影响当前回合。

## 用户看到的研究会话

同页上方保留 Initial Report，下方是 Follow-up Conversation。固定页内导航可快速回看成果或继续提问，没有互斥 Tab。回答按问题需要显示自然段、列表、编号或简单表格；引用直接附在支持正文末尾。用户先读答案，需要时点击来源编号展开逐字证据和真实链接。后台 kind/support 校验保留，前端不强制展示内部语义标签。

耗时操作在后台线程执行，状态查询保持响应；刷新时只查询运行状态，不重新发起研究。完成报告和对话不依赖浏览器内存。

## RAG 和 Memory

Knowledge 按 workspace 数据库隔离，再按 own_product/competitor 领域及产品范围检索。Embedding 召回和 Rerank 排序并用，返回来源及原文。资料替换整体原子提交，旧块删除，失败保留原版本，防止新旧产品事实混用。

Current Focus 是当前任务配置。Memory 是长期用户关注、偏好与限制；自动抽取只能写 pending。用户确认后生效，编辑使旧记录退出，不能被当作产品事实证据。当前产品级 Memory UI 共享 workspace 范围，不声称细粒度租户授权。

## 评测与工程边界

软件测试使用受控替身证明状态、引用、并发、隔离和失败恢复，真实 E2E 证明配置与供应商链路。两者都不自动成为独立质量评测。

历史35条的独立 Baseline 保存原样；参与 Prompt 开发后明确改为开发回归。评测器先白名单适配生产输入，再检查泄漏；答案、选材目标和分布从不进入检测器。正式预测质量只算 SUCCESS，端到端分母含全部样本，错误前原始结果只作诊断。时间评分先验证证据资格，再做确定性日期格式归一。

最终新留出只在 RC 后选材；空候选、Gold 分别 Commit；专家模型独立标注且如实记录，无真人复核声明。最终生产模型每项只执行一次，不因普通错误调参或改 Gold。

## 审计结论与可接受限制

本轮发现并修复的关键问题包括：API 同步模型阻塞查询、刷新运行状态不更新、互斥研究/追问布局、强制追问卡片、引用独立成行、局部事件展示丢失、观察时间混称事件时间，以及旧文档和评测用途漂移。

EvidenceValidationError 的根因是输出未履行严格 Path A/引用契约；保留校验强度，明确模型输出规则，增加安全诊断。旧 Gold 部分使用发布声明判 Event 却标为 Path A，因此开发指标保留真实分歧。

系统保留小模型样本误差、网页不可达、未实现企业认证、无 OCR 与语义蕴含验证不足等明确限制。生产级 SSRF/出口隔离、分布式恢复不是本地作品 MVP 的能力。没有新增复杂工作流引擎、数据库或多智能体体系。
