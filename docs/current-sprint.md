## Done（完成）的统一标准

任何开发 Task（任务）只有同时满足以下条件才可以标记为 Done（完成）：

1. 代码已经实现；
2. 项目负责人本人实际运行过；
3. 验收标准通过；
4. 项目负责人能够解释核心代码的输入、处理和输出；
5. 真实问题或限制已经记录；
6. 完成 Git Commit（代码提交）。

Codex 声称“实现完成”不能单独作为 Done（完成）的依据。任务满足全部条件后，才更新状态并勾选任务清单。

## Task 1：真实 Fixed Source（固定来源）网页读取

**Status（状态）：** In Progress（进行中）

**目标：** 接收一个指定 URL，通过 HTTP 请求读取服务器返回的 HTML，并提取状态码、网页标题和页面文本，为后续 Snapshot（页面快照）与 Change Detection（变化检测）提供原始数据。

**输入：** 一个合法的 HTTP 或 HTTPS 网页 URL，以及可选的请求超时时间。

**处理：**

1. 验证 URL；
2. 发起 HTTP GET 请求；
3. 检查请求异常、超时和 HTTP 状态码；
4. 使用 BeautifulSoup（HTML 解析库）解析服务器返回的 HTML；
5. 提取标题和页面文本；
6. 生成结构化 JSON（结构化数据格式）结果。

**输出：** 正常结果至少包含 `url`、`status_code`、`title` 和 `content`；失败时返回明确错误信息，不把错误页面当作成功结果。

**验收标准：**

- 正常 URL 能获得正常 HTTP 状态码；
- 标题与服务器返回 HTML 中的标题一致；
- `content` 包含服务器 HTML 中存在的主要文本；
- 无效 URL、请求失败、超时和异常 HTTP 状态码能够明确识别；
- 正常结果是合法 JSON；
- 项目负责人本人完成真实 Fixed Source（固定来源）运行验证；
- 完成 Git Commit（代码提交）。

**实际结果：**

- 已实现基础网页读取、HTML 解析、JSON 输出及错误处理；
- Codex 已执行自动化测试，7 项测试通过；
- 项目负责人本人实际运行、最终验收和 Git Commit 尚待完成，因此状态保持 In Progress（进行中）。

**遇到的问题：**

- 当前方案只读取服务器返回的 HTML，不执行 JavaScript（网页脚本）；依赖 JavaScript 渲染主要内容的网页可能无法获得完整正文；
- 是否需要浏览器自动化方案不属于当前任务范围，后续根据真实来源验证结果决定。
