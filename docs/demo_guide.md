# PIA Demo 与项目讲解

## 准备

按 README 启动后端8000、前端5173，使用桌面浏览器（建议宽度至少1024像素）。服务需要现有模型与检索配置。首次启动空状态正常，不要为了演示生成虚假事件。真实数据保存在本机 `.pia-state/`；Git 不带运行数据库、密钥或动态结果。

## 推荐演示路径

1. 自身产品：介绍产品名称、当前关注重点；上传一份可外发的公开演示资料，展示解析入库状态和替换入口。五格式为 DOCX/PDF/XLSX/MD/TXT。扫描 PDF 会明确失败，不能假装 OCR。
2. 关注与偏好：说明主动添加立即生效，自动识别须确认；展示已有确认项与待确认入口。
3. 竞品配置：输入名称与官方 URL，观察来源发现和来源用途。失败保留明确反馈，不伪造监控来源。
4. 首页扫描：首次普通页只建基线；明确声明可能进入历史回溯。展示筛选、状态变化、证据与 Triage。部分失败仍能查看已保存事件。
5. 打开建议研究的事件：用户显式启动，等待时页面仍显示事件和已有证据；刷新可恢复运行状态。研究失败有显式重试。
6. 阅读成果：先摘要，再关键发现、自身影响、建议与后续关注。资料不足时如实说明，不推断“我们不支持”。
7. 同页继续追问：可问“简单解释一下”“总结三点”“和我们对比”“有哪些风险”。报告始终保留，回答使用自然正文；点击行内编号核查原文。不要把来源数量当独立印证数量。
8. 刷新并重新进入：初始报告和追问历史独立恢复；再次打开已完成报告不会重跑模型。

## 本轮实际走查记录

2026-09-28 在真实 localhost:5173 / 8000 页面读取既存事件、分诊、初始报告与两轮对话；对同一事件发出一次新的三点式追问，并在运行中刷新。报告未丢失，回答自动恢复为三段自然语言；来源编号可展开真实摘录。此次是真实产品调用，不是新的独立评测。新增回合保留在本地状态，不提交数据库。

对应故障与形式测试覆盖：不同回答长度、段落/列表/表格、多个引用、无证据建议、来源默认折叠、运行状态查询、接口失败、报告独立持久化与多轮恢复。受控 Repair A/B/C 与资料生命周期 E2E 均检查真实本地存储边界。

## 展示失败时怎么说

- 没有新事件：页面未变、仅建立基线、或证据不足都是合法结果，不能为 Demo 降低事件门槛。
- 模型/网页不可用：界面显示失败，证据与已保存成果不丢；检查本地配置后由用户显式重试。
- 日期未知：展示观察时间并标明含义，不能补作发生时间。
- 资料不足：研究仍能解释竞品，但不能得出无证据的自身能力差异。
- 质量指标：展示评测历史文档，区分历史独立基线、开发回归与最终新留出，不宣称总体准确率。

## 五分钟讲解提纲

先说用户问题：产品经理需要识别有竞争意义的状态变化，而非更多网页摘要。再解释双路径和历史基线为何必要；展示证据如何由程序登记、模型如何解释，最后用研究与追问体现决策价值。

工程重点是 durable outcome 后推进 watermark、独立研究成果、会话原子保存、资料整体替换和按域检索。AI重点是 uncertain、严格引用、Memory 不作事实、有限工具预算。Evaluation重点是先冻系统、再冻空候选、再冻答案、最后一次性评测。

可以说明项目是完整本地单用户 MVP；不要声称已提供定时调度、生产安全、多用户协作、无限轮对话或独立 Research/Memory 质量保证。
